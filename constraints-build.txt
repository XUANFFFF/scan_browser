# 构建约束 —— 固定当前已验证成功的依赖版本组合
#
# 用法（开发用 requirements.txt 仍保持宽泛范围，构建时叠加本约束）：
#
#     pip install -r requirements.txt -c constraints-build.txt
#     pip install pyinstaller -c constraints-build.txt
#
# 为什么需要它：requirements.txt 里是 flask>=3.0 这类宽泛范围，
# 今天能出包的组合，明天重跑构建可能拉到新版本。桌面工具的打包行为
# （PyInstaller hook、pywebview 平台层、PyObjC 接口）对上游版本敏感，
# 出过包的组合必须钉住，升级要显式改这里并重新走完验证。
#
# 版本来源：2026-09-18 实际出包验证的组合 ——
#   Windows  本地 venv（两个 EXE + 冒烟/关窗/双实例全部验证通过）
#   macOS    Actions run 35319778556（arm64 闭环验证 + codesign + 探针全绿）
#
# ⚠️ 与 for-mac-build/constraints-build.txt 保持同步（那边是给 Mac 本地
#    打包用的副本）。升级版本时两处一起改。

# ── 如何升级 ──
# 1. 改这里的版本号（根目录与 for-mac-build/ 两处）
# 2. Windows：重建 venv → build_exe.sh → 冒烟（列表/预览/子目录另存为/关窗）
# 3. macOS：Actions 手动跑 arm64 构建，确认闭环验证（含 codesign）全绿
# 4. 两边都过再提交；只过一边不要发版
